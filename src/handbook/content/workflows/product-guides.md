## Purpose
Run the internal product documentation lifecycle from draft through published Mintlify content and periodic accuracy review.

## When to use it
You support Supervisors on publication policy or audit why Senior Agents cannot “approve” guides in the Hub.

## Who is responsible
| Stage | Owner |
| --- | --- |
| Draft / edit | Supervisor or Admin |
| Ready to publish | Supervisor |
| Publish | Supervisor or Admin with publish access |
| Accuracy review | Supervisor |
| Agent daily review | Agent when assigned on dashboard |

Senior Agent **approve / request changes** on Product Guides is **retired** — do not train it.

## What requires follow-up
- Mintlify and source content updates are manual.
- Wrong published doc: Supervisor edits workflow or team uses Reported Issues.

## Before you approve (ready to publish)
- Walk the publish checklist — broken links and missing Mintlify confirmation block publication for a reason.
- Confirm the guide matches what Agents are told on the floor today.

## What to check (accuracy review)
- Mark **needs update** when product behavior changed; do not leave published guides silently wrong.
- Agent **daily review** on the dashboard is separate from publish — it tracks acknowledgement of assigned guides, not Supervisor sign-off.
