## Purpose
Log internal documentation and operations problems with context, discussion, and ownership — without replacing customer tickets.

## When to use it
You investigate systemic issues, train Supervisors on triage, or verify that resolving an issue does not magically fix source content.

## Who is responsible
| Stage | Owner |
| --- | --- |
| Create | Any support role with access |
| Triage Pending Review (resource-linked) | **Supervisor role** attention queue |
| Work assigned issue | Assignee |
| Resolve / No Action Required | Supervisor or assignee |

Admins with manage access can act, but the **dashboard triage queue** is Supervisor-role-based.

## What requires follow-up
- **Resolving an issue does not update** the Product Guide, Integration, or Knowledge Base record — edit the source or open a new issue.
- General **operations** issues skip the Supervisor-only Pending Review queue pattern for resource-linked types.

## Before you submit
- Link the related guide, integration, or module when the problem is about specific content — it routes triage correctly.
- State what is wrong today, what you expected, and who is blocked.
- Add screenshots or links in the thread so the assignee does not re-ask for basics.

## Before you close
- Confirm the underlying content or process was actually fixed (or document why No Action Required is fair).
- Leave a short resolution note so the next person searching issues understands the outcome.

## If something goes wrong
- Issue stuck in Pending Review: Supervisor attention queue — not every manage holder sees resource-linked triage.
- Customer SLA at risk: handle the ticket in Freshdesk; use Reported Issues for internal tracking only.
